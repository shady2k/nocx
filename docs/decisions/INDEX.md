# Architecture decision records

One row per file in this directory, in the order of the date each record gives for itself,
oldest first. `docs/architecture.md` holds the invariants (`AD-1`…`AD-10`); these records
hold the decisions taken under them and say why each was taken rather than the obvious
alternative.

Read the file, not the row. A one-line summary of an ADR is a pointer, never the
decision.

## Identifiers, as they are now

A new record's identifier is **drawn when the record is created, never counted**: eight
symbols of Crockford base32, lower case, with `i`, `l`, `o` and `u` left out of the
alphabet — 40 bits. `node .githooks/adr-identifier.mjs` prints one, and the file becomes
`<identifier>-<slug>.md`, headed `# ADR-<identifier> — <title>`. Nothing is consulted to
choose it, so two branches adding a record to the same base cannot take one identifier
between them, which is exactly what they did while they counted from the same number.
[ADR-zv62fyqg](zv62fyqg-a-new-records-identifier-is-drawn-never-counted.md) is the decision
and the reasoning.

Records 0001–0105 keep the four-digit numbers they were written with, and their filenames:
an accepted record is never edited, and every citation written against a number has to go
on resolving. So the identifiers here are of **two shapes and never a third** — a legacy
number (four digits) and a draw (eight symbols). `0106` is a record the updater pull
request adds and is accepted: the numbers are retired, not banned.

Rows are ordered by **date**, because a drawn identifier carries no order at all. The date
is the one the record gives for itself — its `Date:` line, or the date it accepts when the
header carries none — never a copy kept here. 0009 is the case worth knowing about: its
number is July because the number was reserved on 2026-07-24, and it sits in September
because the record was written on 2026-09-05.

One check holds all of it, and prints nothing when it holds:

```bash
node .githooks/check-adr-identifiers.mjs
```

It refuses an identifier that names two records, naming every file that holds it; a file
whose name is neither of the two shapes; and a heading that names a different identifier
than its filename. `pre-commit` runs it whenever anything under `docs/decisions/` is
staged, and CI's `ci-backlog` job runs it on every change.

### The numbered era, and what it cost

Accounts of the repairs, kept as history rather than as procedure.

Every number now names exactly one record, and one number was never allocated.

Four numbers used to name two records each. They were repaired on 2026-08-28 (`nocx-yjvg5`):
in each pair the **older** record kept the number, so no citation written against it broke,
and the newer one moved to a free number at the end and carries a **Formerly ADR-00NN** line
in its header.

| Was  | Kept by                                                   | Moved to | Which is now                                            |
| ---- | --------------------------------------------------------- | -------- | ------------------------------------------------------- |
| 0006 | Marker-only prompt mode                                   | 0046     | Reusable credentials for SSH connections (superseded)   |
| 0029 | A proposed keystroke is bound to what makes it meaningful | 0047     | A program may ask; it never chooses                     |
| 0033 | `auto` is the name for "not yet answered"                 | 0048     | UI state is a document, not a setting                   |
| 0035 | The AppImage carries WebKitGTK's helper processes         | 0049     | The channel we own is the carrier, not the command line |

- **0009** — reserved on 2026-07-24 by `nocx-4ff.25` and written only on 2026-09-05. For
  fourteen months of commits the number looked unallocated while the decision it was meant
  to hold — the frozen scrollback is DOM, not decorations over one xterm — was shipped and
  governing. The line that used to stand here said "never allocated; no file with that
  number has ever existed", which was true of the file and false about the decision. That
  is the cost of a reserved number with no record: AD-6 and ADR-0004 §4 went on describing
  a product that had stopped existing, and the gap was found only when somebody reasoned
  from them.

An `ADR-00NN` citation written before that date may still mean the moved record. The
**Formerly** line in each moved file, and the table above, are what resolve it.

Two files also **disagreed with their own filenames**, and the numbers their headings
claimed were already taken: `0036-an-http-upload-route-beside-the-websocket.md` was headed
`ADR-0039` and `0037-an-http-download-route-beside-the-websocket.md` was headed `ADR-0040`,
while ADR-0039 and ADR-0040 are the assistant-turn and block-tree records. The filenames
were free of conflict, so the filenames won: both headings were brought to 0036 and 0037 on
the same date, and each file records the correction in its header. Every other citation of
ADR-0039 and ADR-0040 in the repository means the assistant-turn or block-tree record and
was left alone.

## Adding one

1. `node .githooks/adr-identifier.mjs` prints an identifier.
2. Write `docs/decisions/<identifier>-<slug>.md`, headed `# ADR-<identifier> — <title>`, and
   name the file after the decision rather than the area. Write prose: what was wrong, what
   is decided, why this rather than the obvious alternative, and what the next person
   inherits.
3. Add the row above in the same commit, in the date slot its `Date:` line belongs in.
4. Commit. `pre-commit` refuses an identifier another record already holds, and names that
   record's file.

A change to an accepted record is a **new** record that supersedes it, never an edit. The
new record names what it supersedes in its own status line; the superseded record's row
here gains `Superseded by ADR-<identifier>`, and the record itself is left alone — it is
the evidence of what was decided, at a date.
