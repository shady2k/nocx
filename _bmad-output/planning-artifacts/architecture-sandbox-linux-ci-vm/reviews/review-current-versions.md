## Findings

### 1. P1 — Зафиксируйте полный guest build closure для обеих lanes

**Draft: AD-12, строки 55–58; AD-13, строки 65–69.** Перечня Go SDK + modules + VT assets недостаточно: `main.go:101–104` собирает source helper с `CGO_ENABLED=1` и external linker, а `buildOldHelper` (`448–477`) делает то же самое **в обеих lanes**, включая `packaged`. Ему также нужны executable `git`, `tar`, доступный из рабочего каталога object store с pinned revision, `build/libghostty-vt/vendor` и отдельный generated `internal/helper/notices/licenses/THIRD_PARTY_LICENSES.txt`. Последний не tracked (`Makefile:162–189`), поэтому staging только tracked files его теряет. Без C compiler/linker/libc development inputs сборка fixture остановится до proof. Добавить явный guest inventory: native compiler/binutils/libc headers, git/tar, verified vendor + notices, writable UID1001 HOME/cache/tmp, SDK и module closure текущего и старого дерева. Host `helpers-this-machine` не заменяет эти guest dependencies. Не переносить host musl `CC` вслепую в native builds: packaged helpers используют `vtmusl` и Zig, native smoke — другой build invocation. Сохранить exact downloaded release archives; не заменять их guest rebuild.

### 2. P2 — Согласуйте host runner с заявленным QEMU package

**Draft: Stack, строка 95.** Оба существующих Linux native jobs выбирают `ubuntu-26.04` (`ci.yml:223`, `release.yml:337`), тогда как draft заявляет **host** Ubuntu 24.04 distribution QEMU 8.2. Guest Ubuntu 24.04 не определяет версию host QEMU. [Ubuntu package metadata](https://packages.ubuntu.com/noble/qemu-system-x86) подтверждают для Noble amd64 `1:8.2.2+ds-0ubuntu1.16`, а не пакет Ubuntu 26.04. Явно указать перевод только этих Linux VM jobs на `ubuntu-24.04` либо отдельно документировать источник и supported version host QEMU для оставленного runner. Записывать полную package version и runner image identity; сохранить 60m/30m. Ссылку на QEMU `master` дополнить [versioned direct-boot documentation v8.2.2](https://raw.githubusercontent.com/qemu/qemu/v8.2.2/docs/system/linuxboot.rst).

### 3. P2 — Отделите KVM prerequisite от доказанного hosted-runner support

**Draft: AD-11, строки 44–47; Operational Envelope, строки 100–103.** [GitHub прямо называет nested virtualization experimental и officially unsupported](https://docs.github.com/en/actions/concepts/runners/github-hosted-runners#preinstalled-software-for-github-owned-images), без гарантий performance/compatibility. Поэтому наличие Ubuntu label не доказывает доступ вызывающего UID к KVM и достижимость существующих ceilings. Это конкретный пробел evidence, не утверждение, что hosted KVM никогда не работает. Дополнить design явным preflight доступа к `/dev/kvm` и успешного KVM VM creation для invoking user, явным `-accel kvm` без TCG fallback и acceptance evidence для конкретного runner image; до этого считать CI viability непроверенной. Получение runtime evidence — последующая разрешённая проверка main agent, не выполненная в этом review. Не обходить пробел сменой host kernel, ослаблением ABI, self-hosted migration, retries или увеличением timeout.

## Подтверждённые версии и обязательные детали реализации

- **Linux:** [releases.json](https://www.kernel.org/releases.json) указывает stable `7.2.9`, выпуск `2026-10-03`; [sha256sums.asc](https://cdn.kernel.org/pub/linux/kernel/v7.x/sha256sums.asc) содержит для `linux-7.2.9.tar.xz` ровно `b4c5dfbe51a364a6c7f03869200f88c8e1f77403539005f14b7fc6bc91b8d8ba`. Это сверка опубликованного digest, не локальная проверка скачанного tarball/PGP signature. [Tagged Landlock source](https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/plain/security/landlock/syscalls.c?h=v7.2.9) объявляет ABI **10**; требование **ABI >=9** сохраняется, equality-to-9 вводить нельзя. Built-in Landlock также должен быть активирован при boot; отключённый LSM возвращает `EOPNOTSUPP`.
- **Kernel builder:** [requirements v7.2.9](https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/plain/Documentation/process/changes.rst?h=v7.2.9) требуют, в частности, GCC >=8.1, binutils >=2.30, make >=4.0, flex >=2.5.35, bison >=2.0, bc и Perl; дополнительные OpenSSL/BTF dependencies зависят от config. Назвать builder packages/config отдельно от guest runtime. Go 1.26 и Zig 0.16.0 не являются kernel C toolchain; Zig pin подтверждён repository manifest, Go 1.26 — workflow/module requirement, не exact patch pin.
- **Docker → ext4:** [Docker export](https://docs.docker.com/reference/cli/docker/container/export/) создаёт **tar**, не disk image, и **не экспортирует mounted volumes**. Staged inputs должны находиться в экспортируемом container filesystem, а не только volume. [Noble mke2fs 1.47.0](https://manpages.ubuntu.com/manpages/noble/man8/mke2fs.8.html) поддерживает image-file и `-d root-directory`; его документированный `-d` — каталог, не stdin tar. Зафиксировать export → root extraction в owned builder workspace → `mkfs.ext4 -d` в private raw file, без host loop mount. [GNU tar](https://www.gnu.org/software/tar/manual/html_node/Attributes.html) объясняет `--numeric-owner`, `--same-owner`, `--same-permissions`: extraction обычным host user по умолчанию не сохраняет ownership. Сохранение UID/GID выполнять внутри disposable builder с нужными полномочиями; только итоговый image сделать доступным host invoking user. Это уточнение алгоритма, а не доказанный дефект отсутствующей реализации.
- **isa-debug-exit:** [QEMU v8.2.2 implementation](https://raw.githubusercontent.com/qemu/qemu/v8.2.2/hw/misc/debugexit.c) делает `exit((val << 1) | 1)`; defaults `iobase=0x501`, `iosize=0x02`, access width 1–4 bytes. До реализации определить согласованные port/width и два bounded sentinel values, например guest success `0x10` → host **33**, guest failure `0x11` → **35**. Host принимает только 33 и не теряет его из-за shell `errexit`/logging pipeline; QEMU zero exit не success. Не передавать произвольный process exit code напрямую: shell наблюдает только младшие 8 бит результата, возможны aliases. Нужен root PID1 I/O writer, не обычная печать console marker; отсутствие writer result/panic/timeout — failure. Это конкретизация корректного AD-14, не утверждение об уже существующем buggy decoder.

**Границы verdict:** реальный ABI9+ enforcement, native source + packaged consumers, old-generation assertions и one-origin bytes остаются обязательными. Darwin lint без suppressions и critical npm audit остаются отдельными PR blockers; review не означает release/signing acceptance и не закрывает epic `nocx-a0qhd.16`.

Это не отменяет указанную выше общую оговорку GitHub о nested VM support; cold-run acceptance остаётся невыполненной, но теперь явно предусмотрена design.

### P1 — Не принимайте обычный QEMU failure status за guest success

**Revised AD-14, строки 98–99.** Новая схема guest zero → host **1**, принимаемая как единственный success, совпадает с обычным QEMU startup failure. В [QEMU v8.2.2 `system/vl.c`, строки 2394–2399](https://github.com/qemu/qemu/blob/v8.2.2/system/vl.c#L2394-L2399) неуспешная инициализация accelerator вызывает `exit(1)`; аналогично завершаются malformed options и другие startup errors. Следовательно, VM может не запустить PID1 вообще, но host decoder засчитает proof как успешный. Предварительный KVM preflight не устраняет все ошибки последующего запуска. Использовать bounded sentinel success **0x10 → 33**, failure **0x11 → 35**, принимать только 33; **0, 1, timeout и сигнальное завершение считать failure**. Зафиксировать также совпадающие параметры устройства `iobase=0xf4,iosize=0x04` для заявленного 32-bit writer, поскольку [defaults v8.2.2](https://raw.githubusercontent.com/qemu/qemu/v8.2.2/hw/misc/debugexit.c) иные.

Повторная проверка — только чтение обновлённого spine и primary source; build/lint/tests/VM не запускались, изменён только этот review.
