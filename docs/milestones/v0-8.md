# v0-8 — A fix merged today reaches your installed nocx, on either channel

Charter, approved by the owner on 2026-10-26 (`nocx-inyhw`). Status is never kept here —
ask the tracker: `scripts/feature-status.sh nocx-1ebrs.66`.

## What ships

ADR-0097's trunk-based release pipeline, made real. A merge to `main` is built and
signed as the next nightly; a nightly the owner has tried is promoted to stable without
a rebuild; and an installed nocx on either channel, on macOS and on Linux, updates
itself from inside the app. This milestone is deliberately one outcome: once it works,
a release is a promotion of a tried nightly whenever `main` holds something worth
shipping, and the rest of the backlog reaches people through that pipeline release by
release instead of waiting for a large milestone.

## Outcomes

- **O1: A fix merged to main reaches both stable and nightly installs of nocx on macOS
  and Linux from inside the app** (`nocx-1ebrs.66`, stage `nocx-1ebrs.66.1`).
  **Check:** on Linux, the nightly workflow's own proof step runs the real previous
  nightly AppImage's updater and sees it verify, swap and report healthy on the new
  nightly, and the same proof passes for a stable AppImage updating to a promoted
  stable; on macOS, the owner's pass (`nocx-1ebrs.4`) sees a stable install update
  itself to the next stable and a nightly install to the next nightly. Promotion
  publishes the bytes the nightly verified, and `release.yml` no longer re-runs
  `ci.yml`. **Success signal:** the owner runs the nightly daily and receives each
  day's merges without reinstalling; a stable release takes one promotion command.
  `Serves: local updates users can verify and control (vision §8).`

  The work, in dependency order: the in-app update on macOS, which does not work in
  0.7.x and whose cause is not yet known (`nocx-1ebrs.66.1.1`); the read-only AppImage
  install path that keeps Linux self-update from ever applying (`nocx-azxe.8`); the
  daily signed nightly (`nocx-1ebrs.66.1.4`, which took over `.35.2` and `.66.1.3`); promotion without rebuild, which also ends
  `release.yml`'s re-run of `ci.yml` (`.35.3`); ~~the nightly cask (`.35.4`)~~ — cancelled, one cask and the channel setting
  ([ADR-2syp2fpx](decisions/2syp2fpx-one-cask-and-the-channel-setting-not-two-casks.md)); nightly
  self-update on macOS and Linux (`.35.5`, `.35.6`); and the check of the built
  artifact before publication (`nocx-ngw57`), so the nightly catches what the owner's
  manual pass caught on 0.6.0.

  **Owner addition: the Linux artifacts are decided here** (`nocx-1ebrs.66.1.2`). An ADR
  names, for Flatpak, deb, rpm and AUR, whether nocx ships it, where it is hosted and
  signed, how it updates, and whether it joins this pipeline in v0-8 or a later
  release. Building the formats it admits is filed from that ADR. The decision is
  [ADR-6bs6bk2p](decisions/6bs6bk2p-linux-packages-stay-outside-v08-pipeline.md): the
  native formats are admitted as later-release work and stay outside this pipeline,
  which is why v0.8's Linux story is the AppImage alone.
