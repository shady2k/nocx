# 0.8 — The assistant uses explicitly configured MCP tools on demand

The owner opened 0.8 on 2026-10-23: "давай в 0.8 и поехали разрабатывать"
(start 0.8 and implement). This supersedes the earlier plan-only and branch-only
holds on `nocx-ga29v`. It does not expand the frozen 0.6 release or automatically
activate deferred 0.7 features. Status remains in the tracker.

## Outcome

O1: A person configures an MCP server in Settings and lets the assistant invoke an
explicitly enabled tool through the existing delegate approval flow, without
connecting during startup, setup, search or approval waiting.

Serves: the vision's local-first, bring-your-own assistant and single-machine
secret ownership. Safety of activation and credential isolation takes precedence
over automatic discovery or connection convenience.

The existing feature is `nocx-ga29v`; its complete observable stage is
`nocx-ga29v.8`. The user contract is
[the approved current-main MCP design](../../.internal/specs/2026-10-23-mcp-tools-on-demand-design.md).
The source implementation is PR #181 at
`e4ea37c88fd506c61b49a03035b8ec3eb6bb6615`, not a patch to replay over main.

The acceptance journey creates a stdio server with a dedicated Vault secret,
observes no process before explicit Refresh, discovers and closes the server,
enables a tool, searches without activation, declines without execution, then
approves one exact call and receives a fixture-derived answer. The process closes
at completion. Real-socket HTTP/OAuth, mutation/cancellation, secret-isolation,
revision-conflict and all result-schema checks cover the same full contract.
The actual Settings surface is walked as well as tested.

## Scope and exclusions

Included: stdio and Streamable HTTP, explicit Refresh, local sanitized catalogs,
per-tool enablement, OAuth Connect/Forget and silent renewal, backend-only
system secrets, complete Settings drafts/conflicts, immutable run registries,
existing approval/egress/ledger integration and complete acceptance evidence.

Excluded: MCP resources, prompts, sampling, elicitation, provider-native MCP,
external configuration import, presets, remote helper deployment and SSH stdio
execution. No stdio-only reduction is approved. The opposite-direction nocx MCP
server and external-agent allowlist do not grow.
