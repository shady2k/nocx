# nocx 0.8.0

From this release on, a fix reaches your installed nocx from inside the app — on macOS and
on Linux, on the stable channel or on the new nightly one.

## The app updates itself on macOS

In 0.7.x the in-app update did not complete on macOS. It now does: when a newer version is
published, nocx downloads it, checks its signature, replaces the app in place and restarts
into it. If `/Applications` cannot be written, the update goes to `~/Applications` instead.
After an in-app update, `brew upgrade` finds nothing to do and neither reinstalls nor
downgrades it.

## You see an update when there is one

An indicator in the activity bar says a new version is ready, once per window. nocx checks
when the machine wakes and when the window gets focus, at most once an hour. The release
notes link in the offer opens them in your browser. A failed update says what went wrong in
words, without leaking local paths.

## A nightly channel

Settings → Updates → **Update channel** chooses between **Stable**, the default, and
**Nightly**: a build made from `main` every night it moved. It is one app and one cask; the
channel is only the setting. Nightly builds are signed the same way as releases, but nobody
has tried them before you. Switching back to Stable never downgrades — you stay where you
are until the next stable release.

Every stable release is now a nightly that was tried first, published with the same bytes,
not a fresh build. A build whose identity, version or About fields differ from what it
declares is refused before it is published.

## The Linux AppImage updates itself

An AppImage installed with the install script updates in place from inside the app. The
About page no longer says Linux self-update is install-only.

## Terminal fixes

- **A prompt hook no longer leaves a command stuck as Running.** If a tool or rc file adds
  its own hook to bash's `PROMPT_COMMAND` after nocx's, the hook was treated as a command
  you typed: a block opened that never ended, and the command after it was counted against
  that block. Prompt hooks are now told apart from typed commands.
- **`clear` hides what it cleared, and keeps it hidden after a reload.** It could leave the
  block before it on screen, and a reload could bring a cleared block back.
- **Typing right after Enter reaches the program.** Input for a `read` right after an
  enhanced submit could lose its letters on macOS while Enter still arrived.
- **Scrollback of a session without shell integration keeps loading** the rows that left
  the screen.
- **A question to the assistant about a running command** attaches that command's screen
  even when the shortcut arrives early.

## How to update

From 0.7.x:

    brew upgrade --cask nocx

On Linux, run the install script again or download the new AppImage. From 0.8.0 on, updates
come from inside the app.
