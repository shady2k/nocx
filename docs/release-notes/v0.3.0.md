Two things that usually live in a second application moved into this one: the
assistant now acts inside your scrollback rather than answering beside it, and
nocx has an API client whose collections are files in a folder you own. Files
also cross between machines now, a host you `ssh` into by hand comes up
integrated, and a tab running an agent says what that agent is doing.

## The assistant can act, and every step is a row you can read

v0.2.0 let you ask about a command and read the answer as a block. It can now
run things, and a turn is one entry with everything under it in the order it
happened: the prose it wrote, the tools it called, the commands it ran. Scroll
back through a turn afterwards and you are reading what actually took place, not
a summary of it. Restart the app and the turn comes back off disk and reads the
same way.

When the assistant runs a command it goes through the same path your own typing
does, and the block says who submitted it. A call built on an earlier one says
so in the turn, so a `grep` over a file the previous step found is visibly the
second half of one thought rather than a fact from nowhere. Answers are laid out
as documents — headings, tables, task lists, lists, inline code inside bold,
fenced blocks that show their content instead of their fences — with the same
copy control the rest of the app uses.

Its tools are a closed list and each is named on the wire: list the sessions you
have open, read what is on one's screen, read a file, read a repository's git
status, and run a command. Each is offered only when your policy permits it, and
a call to a tool it was never offered comes back as a result it can read rather
than as a turn that dies. The whole thread of a pane is what it is handed, so it
does not deny the command it just ran; `clear` ends that thread.

Press Stop and the run stops: the prose that already arrived stays, the turn is
marked as stopped by you, and the next question works. Stop sits on the live
turn, in the place a command's Stop already is. A refusal is an answer too. When
a tool call is refused, the assistant is told what refused it — labelled as data
rather than as instructions — and says what it could not do; before, the answer
just stopped. A run cancelled on a host nocx cannot signal says so in the turn.

## Ask without leaving what you are looking at

While a command is running, `⌘`/`Ctrl`+`Enter` opens a question box over it —
including over a full-screen program that owns the whole grid. The screen holds
one frame while the box is open and the program is never told: no `SIGWINCH`,
no resize, `htop` keeps redrawing into a buffer you are not watching. The frame
the assistant reads is the frame you are looking at, not whatever arrived while
it was thinking.

The answer opens in the overlay, where it is readable and scrolls, and then takes
its seat in the scrollback when you dismiss it. `Escape` puts the box away and
gives every key back to the program, and the program's own state is exactly where
you left it.

## Marking, not attaching: you say what a question may read

Nothing attaches itself. Selecting output offers to be marked and marks nothing;
so does the ⋮ menu, which now carries one item — **Ask about this block**,
reading **Unmark** on a block already marked, identical whether the block is
running or finished. A mark covers a whole block, drawn as a rail and a faint
tint rather than as something that looks like a selection, and a block from an
earlier session can be marked too.

What is marked lives on one chip in the composer, which is a count and never a
second list of command names. Clicking it opens the marked blocks; each row can
be dismissed on its own, or all of them at once, and clicking a row scrolls to
that block and flashes its mark. The question names the marked blocks by their
ids and inlines none of their text, so what the model is asked to read is a list
you can see rather than a paste you cannot.

## A yes covers only what you were shown

A `run` proposal reads as a sentence: the command verbatim in its own block, with
the machine it would land on and the tab it would land in as rows beneath it.
That machine is the fact that decides whether a destructive command touches this
laptop or a production host, and it used to be absent from the window entirely.

An answer has a width as well as a direction — **once**, **in this session**,
**always** — and each control says its own coverage next to itself, in the
product's words: `always` names the effect, every session, and no expiry. A
standing yes saves a rule over the exact invocation you were shown, not a row of
the effect matrix, so approving `df -h` grants `df -h` and leaves "make changes
that cannot be undone" at ask. In v0.3.0's first internal builds it granted every
irreversible operation, permanently; that was the defect this rewrite closed.

A rule cannot be broader than what the window showed. A minted rule does not
inherit your own `*`, so an `rm *` you approved once never becomes permission for
`rm /etc`. And a question about a secret leaving the machine is offered as Allow
or Deny once only: "always send secrets to the provider" is not a decision anyone
should make by clicking a button sitting next to five others. What the call is
allowed to do is derived from the command, not from the name of the tool that
carries it.

## You can read what it was told, and what it sent

Settings shows nocx's own instructions to the assistant, placeholders and all,
unresolved — the prompt as written rather than a paraphrase of it. A finished
turn can show its raw dump: what went to the provider and what came back,
verbatim. Between them there is no step in a turn you have to take on trust.

## API testing, without an account

Open a Postman export — a `.json` or a whole `.zip` archive — and it becomes a
folder of ordinary JSON files, one per request. The import ask previews what is
inside and decides once for all of it. Edit a request in a form, press Send, read
the response. Two people editing two requests conflict in two files, and the
whole collection is yours on disk — no account, no cloud, nothing to sign into.

A folder is a place you open, not a row that expands: it opens into the right
half the way Environments does, and shows what is in it. A request can be dragged
into a folder or moved from the menu its row already has, closed when you are done
with it, and made beside the one you are standing in rather than at the root. The
curl ask says which folder the request will land in. The environment a request was
sent under is remembered across a restart.

A request goes out from this machine or from inside an SSH connection you already
have open, and an environment carries both the address and the route to it, so a
production request cannot go around its bastion by the two drifting apart.
Responses are read up to 2 MiB.

## A folder carries variables, and the requests inside it inherit them

Variables now live at three levels — request, folder, environment — and are
edited where you are standing. A folder's page edits its own; a request's
Variables tab shows the whole scope it will send under and says which level
answered each name. The address bar knows the folder scope exists, so a `{{host}}`
resolved by the folder is not underlined as unknown. A folder variable sends with
no environment chosen and no request variable involved.

## A secret goes in any field, and is made where you are standing

In v0.2.0 a credential could only be a variable an environment bound. Now any
value field of a request — a header, a parameter, the URL, the body, Auth —
carries the vault's door: a lock that appears while that field has focus, opening
the same panel `@` opens. What it offers depends on what the field holds. Empty,
it lets you choose a secret you already have. Filled, it offers to take the value
you just pasted into the vault and leave a reference behind, or to replace it with
one you already have.

The file keeps only an opaque handle — not the value, and not the display name you
chose. A secret owns its name, and a name cannot be made to look like a handle. So
a collection you accepted from a pull request cannot reach the password behind an
SSH profile, and an importer never mints a secret out of a credential somebody
else's export happened to carry.

The raw view has three states rather than two. Bytes that match a stored secret
exactly draw a badge naming it. A fragment of one — a token cut off at 24 of 214
bytes, say — draws a badge naming the damage and shows none of the surviving
bytes, because a truncated token is a prefix of a live one. Everything else is
plain text. The bytes are removed before they reach the window, so a renderer
that ignored all of this would still show you no credential.

## A pane says what it is doing

Run an agent — Claude Code, or anything nocx has a driver for — in a pane and the
tab says what its screen is currently inviting: working, waiting for you to type,
waiting for you to answer a permission question, or exited. Three panes in three
states are three different indicators, where before they were one dot that
activating the tab erased.

The classification comes from a driver reading a live grid the backend keeps for
that pane, and it carries where it came from: a pane with a driver is classified,
a pane without one is still lit from its title and says so. Every observation is
bound to the incarnation that produced it, so a late answer from a session that
has since restarted cannot overwrite a current one. A pane nocx is not watching
produces nothing at all, which is the ordinary case for almost every pane.

## Files cross between machines

Drop a file on the terminal and it lands on the machine that tab is on. The Files
tree's context menu does the same on the row you picked, and brings a file back
off the host the other way. On macOS, Show in Finder reveals the file instead of
doing nothing.

Anything in flight shows in the activity bar as a badge with aggregate progress,
and in an Operations panel beside Files, Git and Ports where each transfer can be
cancelled on its own. Collapse the sidebar and the badge stays, so a ten-file
drop is a queue you can watch and stop rather than something happening out of
sight.

## An `ssh` you typed comes up integrated

Type `ssh somehost` at the prompt and the session comes up integrated —
blocks, completion, the sidebar following your directory — while staying your own
ssh process. Your agent, `ProxyJump`, password and 2FA prompts, host-key
questions, port forwards, `-F` and `-o`, and the exit status all still work,
because nocx adds only its multiplex options to what you typed.

Nothing secret goes into the SSH command line any more. The integration bundle
used to be sent twice, once over SFTP and then again inline, and that inline copy
carried the session capability and the recovery fence verbatim: 91,198 bytes of
command line, holding live secrets where any of your own processes on the far
host could read them with `ps`, and where anything recording exec requests would
keep them in a field of its own. The command is 952 bytes now and carries no
secret at all — everything of variable size travels as framed channel data
instead.

## Experimental

Settings, under Developer, has a new Experimental section holding one choice:
how the assistant composes multi-step work. **One call at a time** is the shipped
method and the default — it asks for one thing, reads the result, then asks for
the next. **One program** lets it write a small program instead, so a chain of
dependent steps happens in a single turn and the intermediate results never reach
the model. **One plan** lets it lay out the whole sequence first, which is the
only method that can show you every step before any of them runs.

It is a setting rather than three tools the model chooses between, because a model
picking for itself would measure tool-description salience rather than fitness.
All three obey the same permissions and ask you the same questions: validation,
policy, the attempt record, the narrowed capability, execution and egress
screening happen once, for all three. A carrier is another way to compose work and
never a way round the gate. Not for everyday use.

## Fixes

- The window comes back at the size and position you left it. It had been opening
  at 1024x768 on every launch since the move to Wails v3.
- Terminal geometry settles instead of oscillating. Resizing a pane could put the
  grid into a loop where each refit changed the width that produced it, and a
  display-scale change left a trace behind it.
- `PREVIOUS SESSION` no longer stays painted on top of `htop` and other
  full-screen programs.
- `Ctrl+C` belongs to whatever surface has focus. A selection in the scrollback
  answers it with a copy; a running program still gets its interrupt.
- A sealed vault raises the unlock before a tool result is thrown away, rather
  than failing the call and telling you the details are in a log.
- 77px of dead chrome after the traffic lights is gone. Two notice bars declared
  themselves `display: flex` while marked hidden, which beats the rule that hides
  them, so both owned space on every platform at all times.
- A snippet body wraps at the edge of its box.
- Context menus in the packaged macOS app draw their icons. The labels had been
  indented past a column that stayed empty.
- The ⋮ menu never opens past the bottom of the window.
- The composer no longer jumps ten pixels when you type the first character.
- A tab title in the vertical strip uses the whole row. It had been ellipsing 36px
  early to reserve space for a close button that never sits in the layout.
- Completing a remote path that already contains a slash inserts it once. Typing
  `cd repos/t` and picking `repos/tabby/` used to give you `cd repos/repos/tabby/`,
  which broke every nested completion over SSH including the `cd dir/` step-into.
- An endpoint that answers with an HTTP error says what it said, and an endpoint
  that legitimately takes no key can be configured as one.
- A model that emits its tool call as text is no longer reported as a completed
  answer with the raw markup shown as prose.
- Every JSON-RPC handler on the control plane was read for input validation and
  the findings fixed: acknowledgements follow current subscriber ownership,
  stored hosts fail at the connection sink rather than deeper in, and Unicode
  slug semantics are preserved.

## About

Settings has an About page: version, the commit it was built from, when it was
built, the platform, and the Go and Wails versions behind it. Copy diagnostics
puts all of it on the clipboard, which is the only reason anyone opens a page like
this. No field is ever blank — a value the build does not carry reads `unknown`,
so a row that has not loaded cannot be mistaken for one that has nothing to say.

## Linux: the AppImage runs where it said it would

The 0.2.0 AppImage died before its window appeared on Arch and on anything else
not derived from Debian:

```
ERROR: Unable to spawn a new child process: Failed to spawn child process
"/usr/lib/x86_64-linux-gnu/webkit2gtk-4.1/WebKitNetworkProcess" (No such file or directory)
```

WebKitGTK renders in several processes and looks for those helpers at a path
compiled into the library. The bundler copies what `ldd` lists, nothing links the
helpers, so they were never copied — and on Debian and Ubuntu the bundled library
quietly borrowed the host's copies and appeared to work. The AppImage now carries
the helpers and looks for them inside itself. Every build is verified by running
the finished artefact on Arch, under Xvfb, on a host with no GTK and no WebKitGTK
installed.

## Installing

**macOS**: the app is ad-hoc signed, not notarized, so the first launch needs the
manual quarantine step. **Linux**: `chmod +x` the AppImage.

Both are in the README. nocx is MIT-licensed, and
