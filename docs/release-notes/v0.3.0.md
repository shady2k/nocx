Two things that usually live in a second application moved into this one: the
assistant now acts inside your scrollback rather than answering beside it, and
nocx has an API client whose collections are files in a folder you own. Files
also cross between machines now, and a host you `ssh` into by hand comes up
integrated.

## The assistant can act, and every step is a row you can read

v0.2.0 let you ask about a command and read the answer as a block. It can now
run things, and a turn is one entry with everything under it in the order it
happened: the prose it wrote, the tools it called, the commands it ran. Scroll
back through a turn afterwards and you are reading what actually took place, not
a summary of it. Restart the app and the turn comes back off disk and reads the
same way.

When the assistant runs a command it goes through the same path your own typing
does, and the block says who submitted it. Answers are laid out as documents —
lists, code inside bold, fenced blocks that show their content instead of their
fences, with the same copy control the rest of the app uses.

Press Stop and the run stops: the prose that already arrived stays, the turn is
marked as stopped by you, and the next question works. A refusal is an answer
too. When a tool call is refused, the assistant is told what refused it and says
what it could not do; before, the answer just stopped.

## Nothing attaches itself, and nothing runs unasked

Selecting output no longer attaches it. The selection offers to be attached, and
so do the ⋮ menu and the keyboard, and the composer says what was taken.

A tool call the assistant proposes is checked against a policy you own — a matrix
over what a call does and how far it reaches, edited on the Agent policy page in
Settings. When a call falls outside it you are asked, and "stop asking me this"
lives in the question itself rather than on a page you have to go find.

The composer's chip names the model that will answer, and clicking it is how you
change which one that is. If the assistant cannot answer at all, it says which
step is missing and where to fix it. Endpoints are still configured under
Settings, Assistant, Endpoints, and nothing works before one is.

## API testing, without an account

Open a Postman export and it becomes a folder of ordinary JSON files, one per
request. Edit a request in a form, press Send, read the response. Two people
editing two requests conflict in two files, and the whole collection is yours on
disk — no account, no cloud, nothing to sign into.

A collection file cannot name a secret. Not "is refused": there is no field in
which one can be written. The file names a variable; the binding from that name
to a stored value belongs to the app and never enters the folder. So a collection
you accepted from a pull request cannot reach the password behind an SSH profile.

A request goes out from this machine or from inside an SSH connection you already
have open, and an environment carries both the address and the route to it, so a
production request cannot go around its bastion by the two drifting apart.
Responses are read up to 2 MiB.

The raw view has three states rather than two. Bytes that match a stored secret
exactly draw a badge naming it. A fragment of one — a token cut off at 24 of 214
bytes, say — draws a badge naming the damage and shows none of the surviving
bytes, because a truncated token is a prefix of a live one. Everything else is
plain text. The bytes are removed before they reach the window, so a renderer
that ignored all of this would still show you no credential.

## Files cross between machines

Drop a file on the terminal and it lands on the machine that tab is on. The Files
tree's context menu does the same on the row you picked, and brings a file back
off the host the other way.

Anything in flight shows in the activity bar as a badge with aggregate progress,
and in an Operations panel beside Files, Git and Ports where each transfer can be
cancelled on its own. Collapse the sidebar and the badge stays, so a ten-file
drop is a queue you can watch and stop rather than something happening out of
sight.

## An `ssh` you typed comes up integrated

Type `ssh somehost` at the prompt and the session comes up integrated —
blocks, completion, the sidebar following your directory — while staying your own
ssh process. Your agent, `ProxyJump`, password and 2FA prompts, host-key
questions, port forwards, `-F` and `-o`, and the exit status all still work,
because nocx adds only its multiplex options to what you typed.

Nothing secret goes into the SSH command line any more. The integration bundle
used to be sent twice, once over SFTP and then again inline, and that inline copy
carried the session capability and the recovery fence verbatim: 91,198 bytes of
command line, holding live secrets where any of your own processes on the far
host could read them with `ps`, and where anything recording exec requests would
keep them in a field of its own. The command is 952 bytes now and carries no
secret at all — everything of variable size travels as framed channel data
instead.

## Fixes

- The window comes back at the size and position you left it. It had been opening
  at 1024x768 on every launch since the move to Wails v3.
- `PREVIOUS SESSION` no longer stays painted on top of `htop` and other
  full-screen programs.
- 77px of dead chrome after the traffic lights is gone. Two notice bars declared
  themselves `display: flex` while marked hidden, which beats the rule that hides
  them, so both owned space on every platform at all times.
- A snippet body wraps at the edge of its box.
- Context menus in the packaged macOS app draw their icons. The labels had been
  indented past a column that stayed empty.
- The composer no longer jumps ten pixels when you type the first character.
- A tab title in the vertical strip uses the whole row. It had been ellipsing 36px
  early to reserve space for a close button that never sits in the layout.
- Completing a remote path that already contains a slash inserts it once. Typing
  `cd repos/t` and picking `repos/tabby/` used to give you `cd repos/repos/tabby/`,
  which broke every nested completion over SSH including the `cd dir/` step-into.

## About

Settings has an About page: version, the commit it was built from, when it was
built, the platform, and the Go and Wails versions behind it. Copy diagnostics
puts all of it on the clipboard, which is the only reason anyone opens a page like
this. No field is ever blank — a value the build does not carry reads `unknown`,
so a row that has not loaded cannot be mistaken for one that has nothing to say.

## Linux: the AppImage runs where it said it would

The 0.2.0 AppImage died before its window appeared on Arch and on anything else
not derived from Debian:

```
ERROR: Unable to spawn a new child process: Failed to spawn child process
"/usr/lib/x86_64-linux-gnu/webkit2gtk-4.1/WebKitNetworkProcess" (No such file or directory)
```

WebKitGTK renders in several processes and looks for those helpers at a path
compiled into the library. The bundler copies what `ldd` lists, nothing links the
helpers, so they were never copied — and on Debian and Ubuntu the bundled library
quietly borrowed the host's copies and appeared to work. The AppImage now carries
the helpers and looks for them inside itself. Every build is verified by running
the finished artefact on Arch, under Xvfb, on a host with no GTK and no WebKitGTK
installed.

## Installing

**macOS**: the app is ad-hoc signed, not notarized, so the first launch needs the
manual quarantine step. **Linux**: `chmod +x` the AppImage.

Both are in the README. nocx is MIT-licensed, and
[shady2k.github.io/nocx](https://shady2k.github.io/nocx/) says what it does.
