## What ships

A developer who lives on remote servers always sees what an SSH connection is doing, keeps a
working terminal on a slow or struggling host, and gets the connection back by itself after a
drop or a closed lid. Nobody goes to another terminal because of a nocx failure.

Beside it, as an independent second bet run in parallel (owner, 2026-11-13: «Да»): the assistant
stops being an engine nocx maintains and runs the person's own agent through a harness contract.
The two share no package but the composition root, so neither waits on the other; one that slips
is decided at the milestone's close and does not hold the other back.

The basis is the SSH foundation design (`.internal/specs/2026-11-06-ssh-foundation-design.md`,
ADR-akhhb098, proposed), whose frame and numbers the owner confirmed on 2026-11-06 and which
is not reopened here.

**The first stage is the foundation, and it comes first** (owner, 2026-11-12: «сейчас важно
сделать первый этап — это построить архитектуру и фундамент. У нас не должно остаться вторых
поверхностей, должен быть абстрактный менеджер соединений»): `internal/hostconn` — the state
machine and one supervisor per connection — behind the `Carrier` interface, with an in-memory
carrier in the tests that drives every fault scenario without an sshd. Every second surface for
connection state goes in this milestone: the first-armer keepalive, the renderer's `_liveness`
and reconnect loop, `resolveSshProfileOverlay` and `reopenSSH`'s string match, and the open
logic spread across `internal/app/helper_git.go`.

## Decisions taken while planning (owner, 2026-11-12/13)

- **The renderer decides nothing about a connection.** The backend answers, per panel,
  "available" or "unavailable because …" with at most one action a person can take; the window
  draws that answer. No panel reads a mode or an error string («фронт вообще ни о чем знать не
  должен, это должен решать хелпер»).
- **Git, Files and Ports work only through the helper.** Files over SFTP, port discovery over
  `exec` and each panel's own connection state are removed («можно для простоты вообще убрать
  код работы этих панелей без хелпера»). Where no helper runs — delivery Raw or Script, consent
  refused, a platform the helper is not built for, a plain-ssh tab — the panel says why, with one
  action where the person can change it. SFTP stays where the transport uses it to install the
  helper (ADR-0049). Working without the helper may come back later («Может быть позднее добавим
  работу без хелпера»); it is kept as an idea, not as work of this milestone.
- **A nightly's version comes from the open milestone**: this milestone's nightlies read 0.9.x.
  The milestone keeps its outcome name, and its label carries the version.

## Outcomes

- **O1: An SSH tab shows what the connection is doing from its first second, and never an
  empty screen** (`nocx-oalo1`). **Check:** the fault harness opens a tab and sees a stage
  within 1 s (Q1); a link cut during work reads as silent within 30 s (Q3); a wake signal
  re-reads every tab within 5 s (Q4); Git, Files and Ports read their availability from the
  same answer and no panel matches an error string. **Success signal:** the owner opens his
  hosts for a day and never meets a blank SSH tab.
  `Serves: daily-driving nocx without falling back (vision §9).`
- **O2: A lost connection comes back by itself, and a changed host key stops it**
  (`nocx-oalo1`). **Check:** the harness drops the link and returns the host, including after a
  reboot behind a dead flow: helper-owned shells reconnect within a minute with no command re-run
  (Q5); six tabs on one principal and route make one sign-in and one vault prompt, counted at
  the server and the vault (Q6); a changed host key at reconnect stops and explains with zero
  signatures sent (Q8). **Success signal:** a closed lid or a dropped Wi-Fi costs the owner
  nothing but the wait.
  `Serves: daily-driving nocx without falling back (vision §9).`
- **O3: A slow or broken host still gives a working terminal** (`nocx-oalo1`). **Check:** a
  host silent for 5 minutes after TCP accept connects on that same attempt with no action (Q2);
  with integration broken in every fault scenario the raw terminal takes input (Q7); a healthy
  host paints blocks and never a raw screen, and a repeat open stays near today's 1,436 ms at
  50 ms RTT (Q10). **Success signal:** an overloaded server is slow in nocx, not unusable.
  `Serves: daily-driving nocx without falling back (vision §9).`
- **O4: A typed `ssh host` and the saved connection to that host are one connection, with one
  key** (`nocx-oalo1`). **Check:** for one host with exactly one matching saved connection, by
  profile and by typed `ssh` with no explicit identity, the server sees exactly one key (Q9).
  The typed path on our transport is prototyped first; ADR-akhhb098 is accepted at that stage,
  and if the prototype fails the owner decides between narrowing O4 and moving it on.
  **Success signal:** the owner types `ssh` the way he always has and gets nocx's connection.
  `Serves: daily-driving nocx without falling back (vision §9).`
- **O5: A nightly says which milestone's work it carries** (`nocx-as4ky`).
  **Check:** the first nightly published after the change embeds 0.9.0, a later one 0.9.x, and a
  promotion of one publishes that same version with identical bytes.
  **Success signal:** the version in About matches the milestone the owner is trying.
  `Serves: local updates users can verify and control (vision §8).`

- **O6: The assistant runs the person's own agent, and nocx has no agent loop of its own**
  (`nocx-a62cl`; owner's decision of 2026-11-05 and frame of 2026-11-06, not reopened here).
  **Check:** with pi installed and no model settings in nocx, a question asked from a pane streams
  its answer, a tool call over nocx's MCP endpoint waits for the person's approval and its result
  lands in the same block, and a cancel reaches the tool at once; with no agent ready, invoking
  the assistant opens Settings' agent section; eino is gone from the build. The design record of
  the harness contract and the tool-call pipeline (`nocx-a62cl.1`, superseding ADR-0028) is
  accepted before code. **Success signal:** the same question works through pi, and no new bug
  needs knowledge of model providers.
  `Serves: ask an agent — bring-your-own, including a fully local one (vision §6, Phase 3).`

O1–O3 stand alone if O4 slips. O6 is independent of O1–O5. The design's hand-off (§11) is the stage order: supervisor in the
helper with the fault harness; contract and fold, which ends the empty screen; reconnect; open
order; resolver; typed on our transport. O5 is independent of all of them.

## Finding budget

15, set in `.githooks/backlog-gate/config.json` → `findingBudget` when v0-9 becomes the current
milestone at v0-8-3's close: 10 for the SSH bet and 5 for the
agent bet. busy-terminal took 12 of 12; the SSH scope is designed, but a harness built to break
connections will find defects, and the agent bet moves the tool boundary nobody has exercised.
Raising it admits more unplanned work and moves the end; at 15 something is deferred or traded.
