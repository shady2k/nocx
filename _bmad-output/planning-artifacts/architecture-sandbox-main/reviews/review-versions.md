# Version and integration review

**Scope:** primary-source check of the named Landlock/Seatbelt decisions and the current-main integration facts in the approved architecture/spec and sandbox launch-authority ADR (numbered ADR-0079 during this review, renumbered ADR-0081 after fresh-main integration). This is a source/design review, not a native runtime audit. No sandbox runtime, macOS host, build, or behavioral acceptance was exercised here.

## Verdict

**Conditionally sound as a design contract; runtime and platform claims remain unverified.** The Landlock v0.9.0 ABI9/`RestrictPaths` decision is accurately described with an important scope limitation below. Current-main schema 21, ordered migrate-or-refuse, helper ownership, and additive frozen protocol facts are corroborated by repository sources. Seatbelt's relevant SBPL syntax is demonstrated by a primary project source, but Apple's own position makes the macOS mechanism a material support/longevity risk. The inherited-FD and two-phase readiness behavior are implementation requirements, not facts established by the cited APIs.

## Findings

### VERS-1 — Landlock v0.9.0 ABI9 / `RESOLVE_UNIX`: verified, with precise scope

The tagged [go-landlock v0.9.0 config source](https://github.com/landlock-lsm/go-landlock/blob/v0.9.0/landlock/config.go) defines `V9` as ABI9. Its comments state that with `RestrictPaths`, ABI9 restricts `connect(2)` and `sendmsg(2)` to pathname Unix sockets created outside the enforced Landlock domain, while sockets created within the domain remain accessible. `RestrictPaths` explicitly carries the config's filesystem handled rights and drops network/scoped rights; it is consistent with the filesystem-only decision. The tagged [FS rule source](https://github.com/landlock-lsm/go-landlock/blob/v0.9.0/landlock/path_opt.go) confirms `WithResolveUnix` is an explicit grant and is not included automatically in `RWDirs`/`RWFiles`. The [kernel Landlock documentation](https://docs.kernel.org/userspace-api/landlock.html) describes `RESOLVE_UNIX` among the filesystem rights and ABI9's pathname-socket handling.

**Qualification:** this is not a blanket Unix IPC boundary: the verified rule covers `connect`/`sendmsg` to pathname sockets outside the domain. Linux abstract sockets and TCP/UDP remain outside the selected contract, as the design already states. ABI9 absence must remain an Enforce refusal; silently taking the library's best-effort/downgrade behavior would invalidate this decision. The source confirms the library API and kernel semantics, not that a nocx runner actually applies them correctly.

### VERS-2 — Linux O_PATH pinning through the tagged API: plausible integration, not yet demonstrated

The tagged [Linux rule implementation](https://github.com/landlock-lsm/go-landlock/blob/v0.9.0/landlock/path_opt_linux.go) opens each rule pathname with `O_PATH|O_CLOEXEC` and passes that descriptor as Landlock's `PathBeneathAttr.ParentFd`; the kernel applies the rule to that referenced hierarchy. The official [kernel documentation](https://docs.kernel.org/userspace-api/landlock.html) documents rules as file hierarchies and the add-path-beneath operation. The [proc fd manual](https://man7.org/linux/man-pages/man5/proc_pid_fd.5.html) documents `/proc/self/fd/N` as a symbolic link to the actual open file.

These sources support the proposed mechanism of keeping validated O_PATH descriptors alive and giving the library `/proc/self/fd/N` paths: the library reopens the descriptor link immediately before adding the rule, rather than re-resolving the original user pathname. They do **not** establish the complete prepare-to-apply race guarantee in nocx, nor validate procfs availability, descriptor lifetime, or pathname behavior on its supported Linux environments. Treat identity pinning as a required implementation invariant and native race/retarget acceptance item, not as an already proven property.

### VERS-3 — Seatbelt Unix-socket policy syntax is evidenced; Apple's support caveat is material

The [Anthropic sandbox-runtime primary source](https://github.com/anthropics/sandbox-runtime/blob/main/src/sandbox/macos-sandbox-utils.ts) starts its profile with `(deny default ...)` and documents the three distinct AF_UNIX operations: `system-socket` creation, `network-bind`, and `network-outbound`. It emits `network-outbound` rules using a remote Unix socket path filter and separately scopes bind paths. This validates that the proposed policy can be expressed in the demonstrated SBPL vocabulary; it does not prove Seatbelt behavior or policy equivalence on nocx's target macOS releases. In particular, the architecture must allow the required AF_UNIX socket creation operation while granting outbound/bind only to the launch runtime; allowing just path-filtered connect rules is insufficient to establish all required local IPC behavior.

**Explicit platform risk:** Apple's [sandbox-exec manual](https://keith.github.io/xcode-man-pages/sandbox-exec.1.html) marks `sandbox-exec` deprecated. More importantly, [Apple DTS guidance](https://developer.apple.com/forums/thread/661939) says SBPL/`sandbox-exec` is unsupported as a product foundation. The architecture acknowledges deprecation but does not make the supportability consequence disappear. Therefore macOS Enforce cannot be represented as a supported/stable guarantee from these sources alone; this is an unresolved release/platform risk, not a reason to silently weaken or replace the approved decision. A macOS native probe and positive/negative packaged acceptance are still mandatory, and passing them proves tested behavior only for the tested OS/toolchain combination—not Apple's future support commitment.

### VERS-4 — Inherited policy FD and readiness protocol: requirements, not externally verified facts

The cited [`sandbox-exec` manual](https://keith.github.io/xcode-man-pages/sandbox-exec.1.html) defines `-f` as reading a profile file and `-p` as a profile string on the command line. It does not specify that `/dev/fd/N` is accepted as `-f` input in the intended inherited-descriptor setup, that the descriptor survives the launcher chain, or that a shim can close it before executing the shell. Likewise, neither that manual nor the Anthropic example specifies the design's separate “policy applied” acknowledgement plus close-on-exec shell success/error channel, timeout, or unwind contract.

Those are sensible integration requirements, but **unsupported as current-runtime claims** until the actual runner/helper path demonstrates them. Keep the design's required failure semantics (no successful unrestricted fallback) and make inherited-FD consumption, FD allowlisting/closure, readiness ordering, and failure cleanup explicit native acceptance cases. No implementation workaround is established by this review.

### VERS-5 — Current-main integration facts: corroborated at source level

- `internal/content/sqlite.go` declares `schemaVersion = 21`; `internal/content/schema_migrate.go` defines contiguous 14→15 through 20→21 steps. Its protocol is one transactional edge at a time, refusal for newer/unreachable or shape-mismatched databases, and no reset-on-mismatch. Thus a new 21→22 rung and preservation of existing data/grants are consistent with current ownership; the actual migration is not implemented or tested by this review.
- `internal/helper/session/service.go` says helper owns PTY/process group, inventory and exit status, and survives coordinator replacement; it excludes ContentDB and product policy. `internal/app/helper_local.go` routes local process creation through `OpenHosted` and the helper client. This supports the helper-owned child-launch integration point, not a claim that a future sandbox runner is already wired or that app restart recovery has been validated for sandbox grants.
- `internal/helper/proto/session_service.go` defines the existing `spawn`, `sessions`, and other operations; its comments explicitly distinguish adding a new operation (older helper returns `unknown_op`) from changing closed payload shapes. `internal/helper/proto/abi.go` documents same-UID access and the absence of a session capability. Additive operations with fail-closed unsupported handling therefore match the frozen-ABI premise.
- `frontend/src/panes.ts` documents that restore opens a fresh session when its live-session lookup has nothing to adopt; `frontend/src/terminal-content.ts` has an adoption path that can return to ordinary open. This corroborates the plan's identified fail-closed UI integration seam. The replacement of that behavior for sandbox launches remains a required backend-and-UI change, not an existing guarantee.

## Evidence boundary

Primary sources used: tagged go-landlock v0.9.0 files (`config.go`, `path_opt.go`, `path_opt_linux.go`); Linux kernel Landlock documentation; Linux `proc_pid_fd(5)`; Anthropic sandbox-runtime macOS policy source; macOS `sandbox-exec(1)` manual and Apple DTS forum response. Repository facts above are source inspection of current main. No claim here establishes production enforcement, Seatbelt compatibility across macOS releases, descriptor-race resistance, packaged artifact inclusion, or behavioral acceptance.
