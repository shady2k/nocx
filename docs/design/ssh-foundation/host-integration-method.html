Integration method on the host — connection editor

Task nocx-oalo1.11.2, ADR-727g63tr decision 1: the method (auto, script, raw, helper) belongs to the host, keyed by host-key fingerprint, and the connection editor reads and writes that record. The field stays where it is today — the Advanced section, after Port discovery — and is built from the same kit parts it is built from now: Field (label, description, error), Select (disabled), a cm-hint line and a ghost Button. No new component. Every frame below is the product's own CSS.

1. Host known — the field works, and says whose it is

Edit Connection: prod-db

Set for the machine db-01.internal, not for this connection: every tab to it opens this way, from any saved connection or a typed ssh.

The helper is a binary nocx deploys on the destination. Permission to deploy it belongs to the machine, not to this connection: nocx asks the first time it connects, and every connection to that host reuses the answer.

Applies when you save. New tabs to this machine open with it; a shell already open keeps its method until you reopen it.

Try it: change the method in this frame. The two hint lines below the field appear only while the choice differs from what is stored (changed) and while Helper is chosen (the existing helperHint, unchanged). Nothing is written until Save Connection; Cancel discards the choice like every other field in the editor.

2. Host not known yet — shown, disabled, says when it becomes settable

New Connection

nocx has not connected to this machine yet. It asks how to integrate on the first connection, and you can change the answer here afterwards.

When: a new connection; a saved one that has never connected; a host whose key was replaced (a new fingerprint is a new record). The method cannot be chosen in advance: there is no fingerprint to write it under, and nocx never writes under a guessed key. The select shows the effective value (Auto) rather than disappearing, so the field is where a person looks for it.

Variant 2b — address edited in the draft. The field belongs to the address this connection has saved. While the draft's Host or Port differ from the saved ones, the same disabled select shows Auto, with the description below instead; after Save it resolves the new address (frame 1 if that machine is known, frame 2 otherwise).

3. Loading, and the record could not be read

Could not read this machine's method: settings store is locked

Loading — the lookup starts when the editor opens; until it answers the select is disabled with the placeholder. No spinner: it is a local read and normally faster than the eye.

Read failed — disabled, the backend's reason under the field, Retry beside it (re-reads only). Save stays available: a connection's other fields do not depend on this read, and Save does not write the method while it is unread. Never shown as a silent Auto.

connections.editor.methodRetryRetry — per-surface key, as files.retry, git.retry

Not saved: settings store is read-only

Applies when you save. New tabs to this machine open with it; a shell already open keeps its method until you reopen it.

⚠ The connection was saved, but the integration method for db-01.internal was not: settings store is read-only. Save Connection to retry.

Order on Save: the profile first, then the host record. If the profile fails — the existing “Could not save the connection:” toast, nothing else is written. If the profile is saved and the host record is not, the dialog stays open (instead of closing as on success), switches to Advanced, keeps the chosen value, puts the reason under the field and focuses the select; the toast names both halves. Save Connection retries. Same shape as the existing password-binding split (connections.password.bindingFailedHead/Tail). Save with only the method changed still writes the method — it is a change like any other.

A group cannot hold a default for something that is not a connection's. The row goes from advancedDefaults() and fieldLabel(), with keys connections.group.fieldDeliveryMode, connections.impact.fieldDeliveryMode and connections.editor.fieldDeliveryMode; the — Inherited — placeholder goes from the editor's select too — a host always has a method.

7. Copy outside the editor that now lies

The connect-time ask (host-key-dialog.tsx) says “The method is saved on the connection…”. After this stage that is false. Replace with:

“Choose how nocx integrates with this machine. The method is saved for the machine — every tab to it, from any saved connection or a typed ssh, opens this way — and permission to deploy nocx’s helper here is remembered with it, so this is asked once.”

and keep its last sentence “Change your mind later from the connection’s settings.” — true for a saved connection; for a typed ssh see the open question in the hand-off.
